# Branding Policy

## Allowed branding changes
- App display name: Saifer Browser.
- App icon and adaptive icon assets using the actual Saifer logo supplied by the project owner.
- Explicit app-owned splash/brand graphics and brand-only strings.
- Brand metadata that must identify the generated build.

## Avoid unrelated redesign
- Retain the compact reference-browser layout and interaction patterns where practical.
- Do not add promotional panels, unnecessary gradients, or unrelated UI features just for branding.
- Do not alter browser behavior while performing resource-only branding changes.

## Verification
- Check all locale-specific app-name values.
- Check legacy and adaptive launcher icons.
- Inspect monochrome/adaptive icon behavior on Android versions that support it.
- Search remaining app-owned resources for unwanted old brand strings.
- Confirm changes do not accidentally replace website content or third-party names.

The policy guides engineering work; actual UI parity must be verified against reference screenshots and test runs.
